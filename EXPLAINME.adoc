= EXPLAINME — Trope Particularity (deep-dive)
:toc: macro

The README is the pitch; this is how the vocabulary is structured and kept honest.

== One centre, two axes

The centre is the individuated *property-instance* (a trope, provenance-enriched).
The nine effects sort on two *independent* axes:

* *loss amount* — kept whole (`p-preserving`) vs lost-or-changed;
* *veridicality* — faithful vs *deceptive* (`p-falsifying` / `p-misbinding` /
  `p-conflating` = false value / false bearer / false singleness).

A term belongs only if it bears on individuation or loss and passes the four-part
compatibility test (`docs/background.adoc`): contradicts nothing, writable bridge,
conservative, non-redundant.

== Why "informal by design"

The workbench is the *vocabulary*, not the formalism. The calculus, the IR schema,
and the proofs live with the checker (`trope-checker`), by design (HC-7): keep the
words you think _with_ separate from the machine that checks them. Each effect's
entry gives a *discriminating test* against its nearest neighbour — the part to
carry, not the answer.

== Kept honest mechanically

`tests/check-vocabulary.sh` (`just check`) fails if the nine effects ever disagree
across `vocabulary/`, the trainer, the map, and the README. The `examples/` (duck,
record, person) are kept in lockstep with the checker's conformance fixtures, so a
worked example and the machine verdict cannot drift apart.
